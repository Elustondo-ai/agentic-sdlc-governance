# FG06 — Where these ideas live in Codex

Codex gives us several places to express a workflow. Project instructions establish applicable guidance. A skill describes a reusable procedure and can include references or scripts. Tools provide callable capabilities.

For SDLC2, we can assign a clear responsibility to each part. The governance definition explains what a transition means. Project guidance tells the agent when to consult it. A skill coordinates the work. A schema checks a record’s structure, while a validator checks the conditions we have explicitly implemented. A script performs stable mechanics and returns an outcome.

This is our proposed mapping, rather than a claim that Codex automatically supplies all these SDLC2 checks. We must build and verify the enforcement we need.

A skill can therefore span the formalization gradient. It can contain natural-language judgment alongside precise calls to scripts. We should avoid maintaining conflicting definitions in the skill, policy and program. Each should refer to the governing meaning and expose its own responsibility.

The practical question is always: which mechanism reads this artifact, and what does that mechanism actually do with it?
