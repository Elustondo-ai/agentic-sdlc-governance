# FG03 — What is a domain-specific language?

A domain-specific language is a language designed to express concepts and operations within a particular domain. It provides a vocabulary, ways to combine that vocabulary, and defined meanings.

In SDLC2, words such as sprint, evidence and approval must have shared meanings. A glossary starts that work. A language also defines how we express relationships, valid states, constraints and requests.

Consider the illustrative sentence on this slide. It identifies an operation, a particular sprint, a target state and supporting evidence. We can discuss whether that transition is valid because we have named its parts and defined their relationships.

We can begin with controlled English and introduce more precise notation where it helps. We do not need a new compiler for every concept. But if a machine will interpret a notation, we must define how it recognizes names, resolves references and handles invalid expressions.

The role of a domain-specific language in SDLC2 is to connect human intent with agent interpretation and verifiable action. Mentioning an operation, requesting it and authorizing its execution remain distinct acts.
