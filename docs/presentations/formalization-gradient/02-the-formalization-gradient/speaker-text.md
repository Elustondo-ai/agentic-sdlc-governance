# FG02 — The formalization gradient

Formalization reduces ambiguity by making names, structures, constraints and effects more explicit. The gradient starts with prose and moves through defined vocabulary, structured records and contracts to executable behavior.

Each form contributes something different. A definition establishes a shared concept. A schema checks the shape of a record. A contract states the conditions that must hold. A program performs operations and checks the conditions we have implemented.

These forms can coexist. We still need prose to explain why a rule exists and how to reason about an unusual case. A skill can combine that explanation with records and executable scripts.

This is not a ranking of intelligence or quality. A carefully specified contract may express intended behavior more precisely than the code that implements it. An executable script may also call a probabilistic model or depend on changing external information.

For SDLC2, the practical question is which ambiguity or failure a more formal representation would remove, and whether that benefit justifies the cost of maintaining it.
