# Slide 03 — Visual walkthrough

This slide asks why specifications are becoming important again. The warning across the top links unclear specifications to ambiguity, waste, and risk. It is the problem statement for the comparison below, not a measured result presented with data.

The left column, labelled Waterfall Era, summarizes heavy documentation, upfront requirements, detailed design, and an intended predictable process. Its strength box names clarity, structure, and traceability. The middle column, labelled Agile Era, contrasts working software with comprehensive documentation, less upfront design, user stories, and concern about documentation overhead. Its consequence box warns about lost context, rework, knowledge silos, and fragile systems.

That middle column needs qualification. It is a deliberately simplified account of a failure mode, not a fair description of every Agile team. The Agile Manifesto values working software more highly than comprehensive documentation while still acknowledging value in documentation. It does not prescribe abandoning design or allowing knowledge to become unreliable.

The right column, labelled AI Era, proposes a renewed role for specifications: supply structured context, preserve usable knowledge, support generation and testing, and bring documentation into the workflow. The date ranges are broad storytelling labels, not precise boundaries between universal historical eras.

Across the bottom, specifications lead through AI to code. Read the source-of-truth claim as authority for intended behavior, not proof that the implementation matches it. The slide argues for making intent explicit while continuing to inspect code, tests, and operational results.
