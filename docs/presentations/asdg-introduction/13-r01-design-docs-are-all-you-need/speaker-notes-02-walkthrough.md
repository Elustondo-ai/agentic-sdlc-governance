# Slide 13 — Visual walkthrough

Read the upper row as the workflow depicted in the reference. A design-document dependency graph feeds bounded coding tasks. The coding agents produce a generated symbolic performance-modeling library. Reconciliation then compares results with tests and hand-audited reference models. The dashed return arrow brings failures and ambiguities back to improve the documents.

The lower comparison separates this specialized regeneration strategy from the broader ASDG method. On the left, the durable artifact is a connected set of design documents and the delivery is a rebuilt library. On the right, structured project knowledge supports the engineering lifecycle, with implementation, quality, operations, and observations as evidence. Code may evolve incrementally or be regenerated where appropriate.

The slide's reference to product, release, and sprint should be read with the scope distinction from slide ten: the product roadmap provides direction; release and sprint run the twelve-step cycles. We are not introducing a third recursive lifecycle here.

The final strip names what we propose to borrow: worked examples, dependency links, reconciliation checks, and ambiguity logs. It does not say that all ASDG projects must discard their source code or adopt this paper's delivery strategy.
