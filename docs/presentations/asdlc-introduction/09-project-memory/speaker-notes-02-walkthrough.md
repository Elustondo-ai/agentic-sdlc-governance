# Slide 09 — Visual walkthrough

Read this diagram from the top down, then follow the dashed return path on the right. The top row has five connected areas of project memory. Intent and domain hold use cases, terms, and rules. Design and decisions hold architecture and rationale. Code and evidence connect repositories, tests, and quality assurance. Governance and state identify policies and the current cycle. Observations hold signals, findings, and learning.

The downward arrow gives that shared context to the human-agent pair. The human side names intent, judgment, and approval. The agent side names proposing, building, and checking. Pairing means collaborating over the same project knowledge, not making their responsibilities identical.

The next arrow enters the twelve-step lifecycle. The text inside this box is only a compressed description of the full cycle. It does not replace the twelve named stages with a new four-stage or six-stage method.

At the bottom is the running system, producing usage information, operational signals, incidents, and test and deployment evidence. The dashed line carries evidence back into observations. The words linked, versioned, and reviewable at the top apply to the whole picture: project memory must remain connected to the work and to what actually happened.
