# Slide 09 — Explanation and example

A hypothetical warning feature may pass its automated tests and still annoy people in a realistic conversation. A user observation about distracting timing belongs in project memory alongside the earlier success criteria and design decision.

The team can then ask what the observation means. Is the implementation wrong, is the threshold unsuitable, or did the original use case leave out a common situation? Those are different diagnoses and may require different changes.

The return path is not permission to rewrite the intent automatically. It brings evidence to the people responsible for the next decision. The revised decision should preserve enough history to explain why it changed.

Project memory is therefore not the agent's private recollection or a transcript of every interaction. It is the durable, shared engineering record that remains navigable when a developer, session, or tool changes.
