# Slide 08 — Visual walkthrough

Begin with the three actions on the left: capture, structure, and use. Capture records intent, use cases, rules, and decisions. Structure supplies taxonomy, relationships, and trace links. Use brings relevant context and constraints into the agent's task.

The middle column shows Code Alone. It tells us what was implemented, but rationale may be scattered, context may need to be inferred, and review may proceed file by file. This is a limitation of relying on code alone, not a criticism of having good code.

The right column adds structured knowledge. Intent, tests, and code connect through a domain model of concepts and rules. The resulting view should explain what the system does, why, and under which constraints. Taxonomy organizes the artifacts. Ontology gives meaning to the concepts and their relationships. Governance guides what an agent may do and what it must produce.

The bottom strip prevents a false conclusion: code remains essential. Structured knowledge makes its intent and rationale usable. Agents can propose connections and check some links mechanically, but people still need to judge whether the relationships and the supporting evidence are meaningful.
