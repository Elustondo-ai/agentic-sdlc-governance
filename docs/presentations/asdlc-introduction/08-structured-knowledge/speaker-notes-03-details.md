# Slide 08 — Explanation and example

In a hypothetical conversation model, “speaker,” “turn,” and “warning” are domain concepts. We need to know whether a turn includes short pauses, how a speaker is identified, and what event causes a warning. Defining those relationships is different from deciding which folder stores the document.

That folder decision belongs to the taxonomy. For example, a use case may belong to a particular sprint and link to a reusable component contract. A trace link then connects the contract to an implementation and a test.

A link can exist and still be wrong. A test may exercise a nearby function without checking the behavior promised by the use case. Mechanical link checking establishes that a target is reachable; semantic review establishes whether the target supports the claim.

This is why we should begin with a small, understandable structure. Adding more files, labels, or graph edges is not automatically an improvement. The test is whether the organization reduces guessing and makes an important decision easier to inspect.
