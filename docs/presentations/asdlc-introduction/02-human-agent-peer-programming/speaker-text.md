# Slide 2 — Human–Agent Peer Programming

Now imagine that lifecycle where development actually happens: in a shared project repository. The twelve numbered areas become a working structure. Requirements, use cases, architecture, plans, test results, and release evidence are available to both people and software agents.

This is human–agent peer programming. We work alongside specialized agents. One may implement a change while another checks quality and a third reviews the result. The people remain engaged in intent, design choices, and approval. The robot figures are a visual metaphor for software agents, of course. What matters is that each participant can use the same project context and see the evidence produced by the others.

An agent can start a sprint by reading the current status and the applicable product and release context. It can propose a focused intent, carry work through design and testing, document what happened, and surface issues for human review. The project rules tell it which gates apply and when to stop for approval. The arrows run both ways: instructions and context go to the agents, while code, tests, decisions, and observations return to the shared project.

That is the core idea of SDLC2: an established engineering lifecycle made explicit enough for agents to execute with us, while humans remain able to understand and govern the work.
