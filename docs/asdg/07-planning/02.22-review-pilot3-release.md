# Pilot.3 release preparation

Pablo explicitly requested a full commit, push and release of the latest skills, presentations, README and documentation. This release advances the existing pilot.2 to `0.3.0-pilot.3`; publication authorization is separate from exact-state documentation acceptance.

The portable package adds Help, Update and stable lifecycle team ordering, plus Status-owned post-install onboarding. Existing role, approval, sprint and preservation gates remain. The old published pilot.2 manifest is archived byte-for-byte, verified from GitHub’s checksum-matched ZIP.

The presentation collection is rebuilt from the seven current repository sources, with four available detailed narration editions. Fourteen recent PPTX decks retain their previously verified bytes. The corrected earlier-introduction MP4 is published as a new pilot.3 asset; older release assets are preserved, including pilot.1’s MP4 reserved for manual replacement.

README installation links and presentation downloads target pilot.3. Screenshots supporting the narration correction are retained as versioned review evidence so the published documents do not depend on ignored local preview files.

## Known limits

The earlier introduction’s corrected file hash, captions, video bitstream and frame timestamps are verified. Auditory listening remains unavailable; its public YouTube cut is unsaved, and Google Vids marks its old generated audio as outdated.

Ten videos are recorded public and eleven ready uploads remain blocked by YouTube’s upload limit. Publishing this GitHub prerelease does not clear that external quota or establish native ASDG discovery, invocation or hook trust.

Full package, commit-wrapper and presentation tests are run before publication. An initial package-suite attempt after the version edit used the old manifest and failed integrity checks; preparing the new candidate before the final suite resolves that preparation error without weakening checks.

Presentation visual exports and screenshot evidence are inspected; old raster-backed source visuals remain preserved exceptions. Implementer review uses the same sources and is not independent review or human content acceptance.

The canonical main branch is pushed without force. A new tag/release identifies the exact committed bytes; no existing tag or published asset is replaced. The sample project and its paused upgrade are outside this publication operation.
