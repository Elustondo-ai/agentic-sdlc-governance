## Team first, project understanding second

The canonical Init skill now recommends team setup first and explains the result: one Governance chat plus twelve specialist chats, including Context.
Roles already exist in the installed package. Team setup creates or reuses their conversations; it does not assign project work or start a sprint.
The offered question asks explicitly whether to create that team, with CREATE TEAM or NOT NOW as clear responses. Installation approval authorizes neither team creation nor analysis.
The registered skill is `$asdg-create-team` in Codex; plain “Create my ASDG team for this project” also expresses the request. `/asdg create team` is not a registered command.
Automatic team setup currently requires native Codex project-chat tools. Claude Code uses manual project chats and `/asdg-focus Context`; unavailable automation is never represented as working.
After setup, the suggested Context request describes the work: review the domain, stakeholders, terminology and constraints, report findings and ask about gaps.
This is the existing Context role’s Analyze Context procedure, not a separate survey skill. That work needs its own request.
