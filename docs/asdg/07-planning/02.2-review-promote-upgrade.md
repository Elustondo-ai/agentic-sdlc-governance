# Local promote and upgrade implementation

ASDG Admin implemented the explicitly requested local synchronization commands with Attitude Off.
The intended workflow is preview, inspect differences, then separately authorize an exact apply; real repository synchronization remains unapplied.

![Both directions share a three-way comparison and explicit apply boundary; project state and integrations stay separate.](../../../asdg/docs/images/synchronization.svg)

## Actual implementation

`promote` and `upgrade` share [one synchronizer](../../../asdg/scripts/lib/cli_sync.md) and [snapshot/baseline reader](../../../asdg/scripts/lib/cli_sync_manifest.md).
They validate Git roots, origins, HEADs, provider/version metadata, pilot bindings and stable lifecycle identities.
SHA-256 comparison distinguishes incoming changes, retained local edits and conflicts; every conflict blocks the full apply.
Apply requires the current preview digest, refuses untracked deletions and records incoming hashes/version/commit outside project workflow state.
The portable file list contains 390 members; local adoption records are excluded from synchronization and ZIP creation.
No role IDs, lifecycle definitions, specialist boundaries, skills, hooks or application files were changed by this implementation.
The canonical repository's pre-existing uncommitted consolidation candidate was preserved; this work is layered onto that candidate.
See [usage](../../../asdg/docs/synchronization.md), [test scope](../../../asdg/tests/test_sync.md) and the [technical receipt](02.2-review-promote-upgrade.json).
