# Status owns the next skill recommendation

Pablo requested that “suggestion to create a team should come from … after installation, running the asdg status.”
Codex acted as ASDG Admin within that bounded responsibility correction. Status: REVIEW_REQUIRED.

## Flow and ownership

Installation completes verification, then displays “Next, use /asdg-status in your project chat” and stops.
The Init skill no longer selects team setup, asks a setup question or starts another skill automatically.
Status owns the post-install assessment. For a healthy fresh installation with team setup still needed, it suggests `/asdg-create-team` and explains the Governance plus twelve specialist conversations.
Freshness comes from the installation receipt, not NEW state or empty stage evidence alone. Verified team receipts and project-scoped read-only discovery inform the suggestion.
Unknown/inaccessible inventory remains unknown; advice is conditional. Verified setup, deferral, urgent blockers and facts-only requests prevent blindly repeating setup advice.
Suggestion consumes that Status assessment once before its ordinary NEW/Purpose heuristic. There is no Status/Suggestion recursion or second competing next step.
Native-tool limits and manual alternatives remain with Status. Team setup and Context analysis still require their own user requests.
The deterministic CLI status registration heuristic remains unchanged; the conversational Status skill interprets project/team evidence.
