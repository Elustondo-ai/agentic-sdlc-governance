# Purpose opening assessment

Explicit Purpose selection authorizes this read-only opening. Read the [continuation contract](../../../00-governance/docs/continuation.md).
It also applies to a directly invoked Purpose role. Reading this procedure for maintenance never activates the role.
Keep the known target and prior task; if project identity is unknown, ask for the one identifying fact needed for inspection.

## Inspect before asking

Reuse fresh factual Status evidence when supplied; otherwise inspect the local deterministic status once.
Read the bound client's Purpose documents and relevant existing context, including substantive unregistered material.
Inspect current exact-bundle completion when acceptance matters; distinguish registered artifacts from their substance.
Do not scan all twelve stages merely to open the conversation. Follow a relevant cross-reference when it could change the recommendation.
If evidence is inaccessible, identify that limitation and offer a conditional next step without calling it empty.

## Choose the useful opening

| Observed material | Useful continuation |
| --- | --- |
| Empty or scaffold only | Ask who needs help and what should become easier; do not infer Purpose from code alone |
| Substantive but unregistered | Address its actual outcome or gap; mention registration separately when relevant |
| Partial or ambiguous | Ask about the most consequential missing outcome, boundary or observable acceptance question |
| Contradictory or stale | Name the conflicting claim or changed baseline and propose the smallest clarification |
| Ready for review, not accepted | Present the next review step; do not infer acceptance or record readiness during activation |
| Current accepted baseline | Preserve it; suggest a relevant next contribution or investigate new contradictory evidence |

Briefly identify Purpose, the actual finding and one useful question or recommendation in the same response.
For example, if the draft describes features but no user outcome: “What should the user be able to do more successfully?”
Use the user's prior answers and deferrals; do not restart a generic interview or repeat dismissed advice.
When accepted Purpose is sufficient and use cases are the consequential gap, an advisory Use Cases pointer is appropriate.
Verify the existing selector before naming it; this neither selects a peer nor claims coordinator delivery.
No useful Purpose gap means no invented Purpose work.

## Assignment and write boundary

If selection includes an assignment, begin it within the current role contract instead of adding a redundant opening interview.
Pure assessment, diagnostic questions and replies to them remain conversational unless documentation work is actually assigned.
An assigned Purpose interview or documentation task follows the [delivery procedure](SKILL.md) and its existing completion criteria.
Activation alone creates no documents, image, review event or lifecycle change, and starts no sprint.
Do not treat agreement with a suggestion as authorization to save, accept or implement an unseen deliverable.
Report the actual title-update result separately; a failed or unavailable rename does not prevent useful continuation.
Finish an authorized assignment before recommending its next increment; honor a request to pause or stop.
