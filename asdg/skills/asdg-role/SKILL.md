# ASDG Role — explain the current mandate

## Establish the selected role

Use this conversation's successful activation/clear receipt; never infer selection from a title, directory or available adapter.
With no explicit selection, explain the default 00 Governance role; there is no role-less mode.
Treat Governance, default or explicit, as ASDG-COORDINATOR / 00, outside the twelve stages; [ASDG Admin](../../admin/AGENTS.md) is separate and only explicitly selected.
If activation history is lost, report Unknown — reactivation required; do not reconstruct it from other chats or user-wide logs.
A retained selection with missing guidance stays selected but blocked; report which definition is unavailable.
Resolve its existing entry and procedure through [the catalogue](../../00-governance/types/agent-catalog.json).
Read that role's entry, contract, procedure, shared runtime rules and task-relevant linked allowances in full.
Label reads performed now as inspection, not retrospective activation evidence; reading never activates or refreshes focus.
Use current contracts for bounded write/review allowances; do not assume every role is read-only or every focused agent can implement.

## Explain the role in the user's project

Lead with role name/ID, its purpose and the target project.
Use the [session declaration](../asdg-focus/session-state.md); distinguish the current subject and thinking attitude from the role's responsibility, without changing any field.
Explain its owned responsibilities, expected inputs and useful outputs in plain language.
Explain direct capabilities, explicit exclusions, applicable allowances and decisions reserved for the human.
Distinguish a role's responsibility from runtime permission, active sprint scope, approval and actual execution.
Explain how it works with other roles and handles an out-of-scope request; do not silently select peers or delegate.
Use one relevant in-scope example and one excluded example when helpful; keep them hypothetical.
For Governance, describe the whole-project view: goals, evidence, cross-stage dependencies, routing and human decisions.
For a specialist, explain its contribution without replacing adjacent responsibilities or inventing a lifecycle stage.
If a requested capability depends on current project state, inspect that fact or state the dependency; do not grant permission by description.
Keep operational progress, Git summaries and full workflow state in [Status](../asdg-status/SKILL.md).
Keep next-step recommendations in [Suggestion](../asdg-suggestion/SKILL.md).

Return a concise role explanation with the canonical sources actually inspected and any material uncertainty.
Do not start an interview, perform the assignment, create files, activate/clear focus, rename, delegate or change state.
