# Verify the reporting skill in a disposable client

| Case | Observe |
| --- | --- |
| ASDG-02 Purpose | Three Purpose slides with spoken notes and references. Zero child dispatches. Topic and role remain stable. |
| Governance, all available | Twelve real role activations and returns, twelve captured sections, 36 slides in order, and an actual readable PPTX. A fresh reader can inspect each receipt after workers exit. |
| Small host pool | With a capacity of three, schedule twelve assignments in waves. Capture each completed packet before releasing its slot. Slide order stays stable when workers finish out of order. |
| One unavailable specialist | Eleven valid sections and one coverage slide yield a 34-slide PARTIAL report. The missing role and reason are visible. No inferred content. |
| A specialist has no current evidence | Its three returned slides identify the searched sources, unknowns and next evidence to collect. Its contribution counts as returned; its project status stays unknown. |
| No native role delegation | Block the Governance run. Do not replace twelve native activations with a single narrator or twelve permanent chats. |
| Admin, ambiguous binding or invalid role | Route only with a verified lifecycle/Governance role and client. No silent role switch. |
| Malformed packet, stale snapshot or denial | Record the exact gap and retry only as allowed. A second run preserves prior evidence; no cross-owner or application writes. |
| Source-only handoff | Open the illustrated presentation README and follow every SVG, speaker-note and shared-image link with no build directory or renderer. |
| Rebuild | Rebuild from the handed-off source folder without worker packets or a previous PPTX. Check an edited note reaches its own slide and source hashes stay unchanged during export. |
| Renderer unavailable | Deliver complete sources, identify the missing export dependency and keep export status separate. |
| Regression | Ordinary asdg-status stays a concise chat report with zero file writes or delegation. |

Run the distribution tests for ZIP installation/relocation and `test_report_project_status.py` for deterministic packet, coverage and stage order checks. The provider renderer integration test requires its documented Python dependencies and system Cairo. Read the test summary for skipped cases. Native dispatch, release and host guard behavior still require a live client.
